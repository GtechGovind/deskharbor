# Native video surfaces

Use `NativeSurface.create(sessionId)`, then `present()` for each Rust FrameReady event, and `Texture(textureId: surface.textureId)`. Dispose when leaving the session. Only identifiers cross the method channel; decoded bytes remain native. Missing frames submit a real transparent native clear and return `frame_unavailable`; this is an empty presentation, never a successful generated video frame. The UI may also hide the texture while unavailable. Creation registers an empty texture; it does not assert that a decoded frame exists.

The application must initialize its FRB engine once before creating surfaces. Package the **same dynamically loaded dh_ffi library**, including the frame C ABI, beside the Windows runner (`dh_ffi.dll`), in Linux `bundle/lib` (`libdh_ffi.so`), in macOS `Contents/Frameworks` with the runner's framework rpath (`libdh_ffi.dylib`), or Android `jniLibs/<ABI>` (`libdh_ffi.so`). Do not statically link another engine into this plugin. The plugin holds its module handle until process exit so outstanding renderer leases can safely release.

Windows uses PixelBufferTexture and an immutable native-owned RGBA snapshot copied once in `present()`. The Rust lease is released as soon as that synchronous copy stops reading it, including allocation/error paths. Renderer completion retains/releases only native-owned storage; repeat paints need no Rust lease or second engine lookup. Missing data atomically replaces the pending snapshot with transparent pixels and schedules that clear before returning an error. Stable descriptors survive through asynchronous unregister completion.

Linux uses FlPixelBufferTexture and one engine-scoped raster-only staging allocation (at most 128MiB), rather than one pixel vector per texture. The pinned engine calls copy/upload synchronously and serially on its dedicated raster thread. UI disposal clears the pending native-owned snapshot but never mutates staging bytes. A retired GObject remains alive across borrowed lookup -> callback -> upload and through the queued engine unregister operation.

Linux disposal has a private, ticketed handshake while preserving the public `Future<void> dispose()` API: native `disposeTexture` unregisters and returns a monotonically increasing ticket; Dart rasterizes only an offscreen blank 1x1 Picture; its completion is a FIFO fence behind unregister on the pinned dedicated raster task runner; `collectDisposedTextures {ticket}` then releases only retirements covered by that fence. A newer retirement cannot be collected by an older ticket. No application canvas, desktop or remote pixels are read by this lifecycle fence. Upload completion alone is not used as an unregister fence.

An owned cleanup EGL GLES context is created on the first raster callback by sharing the actual current render context through public EGL APIs. After the fence, native cleanup makes that context current, deletes retired objects/GL textures and restores the prior context. No Flutter engine handle or private struct layout is accessed. Non-EGL, desktop GL and custom merged platform/raster runners are unsupported. Context/fence/unregister failures return `cleanup_unavailable` with recovery guidance and retain objects safely; at most 8 total active/retired objects are allowed, so failure cannot grow retention without bound. Normal disposal completes only after collection. Final engine weak-finalization drains remaining metadata after synchronous engine Shutdown; that path skips the pinned base's GL-delete-only dispose because the context already reclaimed GL resources, then chains GObject disposal/finalization. Revalidate these source contracts when changing Flutter versions.

Windows/Linux snapshots are bounded to 128MiB per presentation and add one native RGBA copy/allocation per accepted present. The current owned copy supports repeat paints; superseded copies are freed after in-flight native renderer readers finish. Linux additionally copies into its one engine-scoped staging pool on a paint. Disposed Linux metadata does not keep a full per-presentation copy. This trades an explicit native memory/copy cost for prompt Rust lease release; no video pixels travel through Dart.

Linux records its first EGL-setup or staging-copy failure atomically. The next create/present reports `renderer_initialization_failed` or `renderer_copy_failed` with recovery guidance, rather than acknowledging further valid engine frames. Pending native content is cleared. Safe no-GL-resource disposal still collects owners, but returns that known renderer failure; a surface never rendered is distinguished from one that failed initialization. The first present notification is request acceptance, not a GPU/display proof.

macOS FlutterTexture converts RGBA to a retained BGRA CVPixelBuffer and uses a preallocated transparent CVPixelBuffer when data disappears. Only the Objective-C plugin header is public; C-compatible helpers are private and C++ helpers are excluded from the pod. Android SurfaceProducer retrieves the current Surface for each draw, copies RGBA with ANativeWindow destination row stride, and posts a 1x1 transparent native buffer before reporting missing data. It releases its source/window on every path and its producers on detach. Android targets API24+, compileSdk37 and NDK28.2.13676358. All platforms preserve top-left row order without vertical inversion. Rust libraries must match every runner ABI (including Android arm64-v8a and x86_64); 32-bit architectures require a matching engine library too.

Linux and macOS resolve the engine from the canonical executable bundle path used by FRB, without relying on the caller DSO's inherited loader search paths, and retry an unavailable lookup at surface creation. Windows first retains an already-loaded dh_ffi DLL; Android uses the packaged JNI library name. No native plugin creates an engine.

`common/dh_frame.h` defines the C ABI and caller obligations. No native plugin creates an engine. Missing ABI symbols return `library_unavailable`; missing decoded frames return `frame_unavailable`. Native output failures return an explicit error instead of a generated success frame.

## Verification

- `flutter test` and `flutter analyze` from this package.
- `rustc --edition=2024 --test packages/native_surfaces/tests/rust/lease_harness.rs -o <scratch-exe>` from the repository, then execute it. This includes the actual FFI helper implementation with only the engine/DecodedFrame dependency boundary supplied by the harness. `cargo test -p dh-ffi` runs the same tests against the real engine/media crates.
- Compile and run `tests/native/copy_test.cpp`, `lease_test.cpp`, `presentation_test.cpp`, `library_path_test.cpp`, `owned_snapshot_test.cpp` and `renderer_health_test.cpp` with C++17, warnings as errors, and AddressSanitizer. They exercise the exact pixel-copy and atomic-release helpers used by the plugins; corners detect RGBA/BGRA mistakes and row inversion, while the lease test exercises two racing completion calls and shutdown release. Presentation tests cover missing-data clears, invalidation after acquire, disposal before callback, disposal after copy before upload, cross-texture staging reuse, and 50 controlled dispose/upload cycles. Path tests cover relocated bundle paths and bounds. Owned-snapshot tests verify prompt Rust release without another present/dispose, repeat paints, allocation failure clears and pre-allocation bounds. Renderer-health tests inject setup/copy failures through the production preparation and public-error seam. A compile-only loader-header target keeps strict C++17 warnings enabled. CMake/CTest configuration is in `tests/native` with optional `DH_NATIVE_SANITIZE=ON`.
- Windows plugin can be checked with MSVC `/Zs /std:c++17 /W4 /WX /EHsc /DNATIVE_SURFACES_PLUGIN_IMPL` against the Flutter SDK engine and cpp_client_wrapper include directories.

A passing helper test or source compilation is not a displayed-video proof. Each packaged runner still requires a real Flutter texture upload, resize, unavailable-frame, background/resume, and detach smoke test. Do not use an actual user screen or input injection for these tests; feed deliberately labelled corner fixtures.
